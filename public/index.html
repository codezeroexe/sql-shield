One string. Two ways the database reads it.

SQLShield runs the same classic bypass payload through both query constructions against the same database. Bound as a value it can only ever be data. Interpolated into the statement it becomes syntax, and prints back every row it was never allowed to see.

This runs exactly as typed against the live demo database. It can read every row, and it can write. database.sqlite is deleted and reseeded from four hardcoded users on every boot, and it holds no real credentials. db.all compiles one statement per call, so anything you type after the first ; is reported as never compiled rather than quietly run.

Mitigation skeleton

            in order — each step depends on the last
          

          
    
            
  1. 
              Trust boundary
              Input arrives here. Everything downstream treats it as hostile by default.
            
    2. 
            
  2. 
              Validation
              Required fields and expected shapes, checked before any statement is built.
            
    3. 
            
  3. 
              Parameter binding
              Values travel beside the statement, never inside it. The fix for everything above.
            
    4. 
            
  4. 
              Least privilege
              The database account holds only the permissions the app actually uses.
            
    5. 
            
  5. 
              Result handling
              Return the columns the caller needs, and nothing more.

  6.
